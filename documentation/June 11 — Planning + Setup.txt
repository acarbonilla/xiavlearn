# XiAv Learn — Day 1 Foundation Documentation

## Date

June 11, 2026

## Project Name

XiAv Learn

## Project Type

AI-powered English learning journey platform using orchestrated AI agents.

## Day 1 Objective

The objective of Day 1 was to finalize the project foundation before building the AI features. The focus was on project planning, backend setup, database design, agent workflow, and preparing the Django project for development.

## Project Summary

XiAv Learn is a multi-agent AI learning platform designed to help English learners improve through a structured and measurable learning journey. Instead of allowing learners to practice randomly, the system diagnoses their current skill level, creates a personalized curriculum path, teaches lessons, tracks mastery, schedules study activities, and provides coaching feedback.

## Problem Statement

Many English learners practice without knowing which skill they should improve next. Existing AI tutors can answer questions and generate lessons, but many do not provide a structured learning path, continuous progress tracking, or clear improvement direction across grammar, vocabulary, speaking, listening, and pronunciation.

## Solution Statement

XiAv Learn uses multiple specialized AI agents to guide learners through a personalized English learning journey. The platform evaluates the learner, selects the right curriculum path, provides lessons, tracks skill mastery, creates study plans, and gives coaching advice based on performance.

## Approved Agent Workflow

The approved MVP agent workflow is:

Diagnostic Agent
→ Curriculum Agent
→ Teacher Agent
→ Tracker Agent
→ Scheduler Agent
→ Coach Agent

## Agent Responsibilities

### Diagnostic Agent

Evaluates the learner’s current English level and skill weaknesses.

### Curriculum Agent

Selects the correct learning path based on the learner’s level and skill mastery.

### Teacher Agent

Provides lessons, practice activities, grading, and feedback.

### Tracker Agent

Updates the learner’s mastery scores after each session.

### Scheduler Agent

Creates personalized study plans based on weak skills and target goals.

### Coach Agent

Explains progress, motivates the learner, and recommends next steps.

## MVP User Flow

The MVP user flow is:

1. User registers or logs in.
2. User takes a diagnostic assessment.
3. System generates a skill profile.
4. Curriculum Agent selects the correct module.
5. Teacher Agent provides a lesson and exercise.
6. User submits an answer.
7. Teacher Agent gives feedback and score.
8. Tracker Agent updates mastery scores.
9. Scheduler Agent recommends a study plan.
10. Coach Agent gives a progress summary.

## Technology Stack

The selected technology stack is:

* Backend: Django
* API Layer: Django REST Framework
* Database: PostgreSQL
* Environment Configuration: python-decouple
* Authentication: Django built-in authentication
* Diagramming: Lucidchart
* Documentation: OneNote / README.md

## Database Decision

PostgreSQL was selected because it works well with Django and supports JSONField, which is useful for storing flexible AI-generated data such as study plans, objectives, and agent outputs.

## MVP Database Tables

### users

Stores account information using Django’s built-in User model.

### learner_profiles

Stores learner-specific information such as current level, target level, study time, and learning goals.

### skills

Stores the main English skills being tracked:

* Grammar
* Vocabulary
* Speaking
* Listening
* Pronunciation

### skill_mastery

Tracks each learner’s mastery score per skill.

### curriculum_levels

Stores CEFR-based levels:

* A1
* A2
* B1
* B2

### modules

Stores learning modules connected to a curriculum level and skill.

### study_sessions

Stores each learner’s lesson or practice session, including input, AI feedback, and score.

### study_plans

Stores personalized study plans generated by the Scheduler Agent.

## Approved MVP Simplification

For the hackathon MVP, the database will start with a simplified structure.

Separate diagnostic_results and session_feedback tables will not be created immediately. Instead:

* Diagnostic results will update skill_mastery directly.
* Teacher feedback will be stored inside study_sessions.
* More detailed history tables can be added later after the MVP is working.
